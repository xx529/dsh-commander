# 任务详情抽屉 · 方案原型

对 `dsh-commander` 看板右侧「任务详情」抽屉的重新设计。现状（2026-11-18）是分区平铺：概览 → 决策记录 → 验收内容 → 关联会话 → 时间线 → 人工改动，全部同权重堆叠，长验收文本与证据挤在同一行，操作按钮在最上方。

先给 A/B/C 三个**结构不同**的方案；在「进度条 + 编年顺序」的方向上又合并出一个 **D（默认）**。C 的倒序只留作对照。

## 打开

双击 `index.html` 即可（纯静态，无构建、无依赖）。也可以用本地 HTTP：

```bash
python3 -m http.server 4173 -d prototype/task-detail
# http://localhost:4173/?variant=A
```

参数：

| 参数 | 取值 | 说明 |
|---|---|---|
| `variant` | `A` / `B` / `C` / `D` | 方案，默认 D |
| `theme` | `dark` / `light` | 主题，默认 dark |
| `status` | `review` / `draft` | 示例任务状态，默认 review（待验收） |

底部浮条：左右箭头切换（`←` / `→`），`1`–`4` 直达；右半边可切示例状态与主题。浮条会自动居中在「抽屉之外的可见看板区域」，避免压住抽屉底部操作条；窗口太窄时抽屉会让出底部一条，浮条落到抽屉下方。

## 四个方案

| | A · 审阅台 | B · 双栏检视 | C · 事件卷宗（对照） | **D · 编年审阅（默认）** |
|---|---|---|---|---|
| 宽度 | 460px | 720–880px | 520px | 520px |
| 结构 | 单列分区：头部摘要 → 验收 → 决策 → 会话 → 折叠时间线 | 左内容右上下文轨：验收/会话/改动 + 状态/决策/时间线 | 顶部进度 + 决策卡，事件流**倒序** | 顶部进度 + 摘要，事件流**正序**（创建 → 最新 → 现在），底部操作条 |
| 验收证据 | 默认收起 | 常显 | 折叠 | 摘要常显，完整证据可展开 |
| 主动作 | 底部固定操作条 | 顶部动作区 + 轨底 | 顶部「待你确认」卡 | 底部固定操作条 |
| 适合 | 日常审阅，动作路径最短 | 复杂任务，一屏看全 | 只看最新进展 | 既要知道来龙去脉，又要快速验收 |
| 代价 | 详情多时要滚 | 占屏大 | 与阅读习惯相反 | 首次打开要滚到最新（头部有「验收 3/3 ↓」直达） |

D 是合并版：进度条来自 C（顺序改为最早在上），操作条 / 证据折叠 / 紧凑头部来自 A，决策回执 / 会话卡 / 状态上下文 / 证据摘要常显来自 B；同时删掉了 A 里「分区 + 时间线」的重复叙事。四份实现互不共享布局，只共用 token 与原子控件（按钮、状态 chip、证据块）。

## 数据与边界

- 数据取自 2026-11-18 的真实任务截图（Research 工作区、`/prototype` 技能调研、3 条验收、2 个派发候选），另补了少量示例事件用于撑起时间线。
- 字段对齐真实契约：`TaskView` / `TaskDetailView`（acceptance / dispatch / sessions / timeline / boardEdits），没有引入新字段。
- 这是抛弃型原型：无测试、无持久化、按钮不落库。选定方案后再按仓库的 Host/Client 分层把赢家落回 `packages/dsh-commander/src/client`。
- D 只用现有字段就能实现：以 `timeline`（created / dispatch / report / user_edit / status / accept / rework）为时间轴；`dispatch` 挂到 dispatch 事件，`sessions` 按 dispatch 事件的 `sessionId` 挂成会话卡，`acceptance[]` 挂到 report 事件；没有对应时间戳的会话退化为「关联会话」事件放在末尾；`boardEdits` 非空时按 `at` 插入「人工改动」事件。
- 之所以不做成真实路由（SKILL 的 sub-shape A）：插件 Client 必须跑在 DSH Web 壳里，改真实路由要重装 + 重启用户的 live DSH；独立 HTML 能立即看、可截图、可分享。
