# 指挥官面板 · 交互重设计（C 为主，A/B 对照）

针对 2026-11-18 live 面板的问题：**派发确认卡和审批卡都渲染在对话流里**，和消息抢注意力；绑定信息只有一枚「已绑定」pill；进行中的任务默认折叠；确认后发送的 `[dispatch-confirm]` 协议消息直接以一大段原始文本出现在蓝色气泡里。

这不是一个页面从零设计的问题，而是「**这些状态该住在哪里**」的重排。三个方案结构不同：动作坞、独立收件栏、浮层抽屉。都保持「派发先确认」「审批只在界面处理」两条产品约束。

**2026-11-19 更新：C 已落回生产客户端并 build；悬浮球重做（去红 badge/绿点/外描边，品牌蓝或石墨、实心旗标、琥珀计数 + hover 标签）。** 实现与验证见 `docs/validation/client-c-panel.md`。A/B 保留在浮条里做对照。

## 打开

```bash
pnpm prototype:panel
# → http://127.0.0.1:4310/   （默认 C）
# → http://127.0.0.1:4310/?variant=A|B   对照另外两套骨架
```

不想起服务也可以直接双击 `index.html`（纯静态、无构建、无外部依赖）。

| 参数 | 取值 | 说明 |
|---|---|---|
| `variant` | `C` / `A` / `B` | 方案，默认 **C**；A/B 保留对照 |
| `theme` | `dark` / `light` | 主题，默认 dark |
| `conn` | `live` / `polling` | 连接状态，默认 live；`polling` 展示提示条 |
| `sheet` | `1` | 仅 C：初始展开处理抽屉 |
| `ball` | `blue` / `ink` | 悬浮球样式，默认 blue；`ink` 是石墨版 |

底部浮条：`←` / `→` 或 `1` / `2` / `3` 切换方案；`重置` 恢复场景；`断线` 模拟 SSE 降级；`浅色` 切主题；`状态` 显示本地演示状态 JSON；`D` 键也能开状态。

## 三个方案

| | A · 待处理坞 | B · 双栏收件箱 | **C · 处理抽屉（默认）** |
|---|---|---|---|
| 尺寸 | 420×660（沿用） | 600×660（需要放宽） | 420×660（沿用） |
| 派发/审批位置 | 顶部固定坞；`派发确认 / 审批` 两个 tab，一次只展开一张 | 右侧独立收件栏，卡片平铺 | 底部抽屉，遮罩层；对话区不出现卡片 |
| 绑定信息 | 标题下第二行：会话标题，点开浮层看会话 id / 工作区 / 模型 / 连接 | 顶部三列常显：会话 / 工作区 / 模型 + 换绑 | 顶部状态条 + 「指挥状态」浮层（绑定 + 任务 + 连接） |
| 进行中的任务 | 折叠任务轨：进行中/待派发数量 + 当前任务 + 进度，可展开全部 | 右栏「任务」tab：状态、进度、最近更新 | 状态条计数 + 浮层任务列表 |
| 提示 | 横幅（降级/重试/忽略）+ composer hint | 对话列顶部横幅 | 状态条 + 横幅 |
| 对话区 | 只有消息和决策记录 | 只有消息和决策记录 | 只有消息和决策记录 |
| 适合 | 保持 420 宽，动作多时也不挤对话 | 需要同时看到任务与待办 | 最干净的对话，动作按需展开 |
| 代价 | 动作坞展开时对话只剩约 1/3 高 | 面板变宽，需要产品确认 | 处理动作多一步点击；抽屉会遮住对话 |

三套方案的派发卡、审批卡内容相同（标题、目标、置信度/阈值、命令、原因），只是各自换了骨架；不共享布局，只共享 token 和按钮/芯片原子。

## C 的悬浮球重做

旧球的问题不是蓝色，而是**同时有三个高音信号**：红 badge、常驻绿点、深色外描边，再叠一个线条旗标；远看像聊天头像，近看像状态灯堆在一起。

新球只保留一个计数信号：

- 品牌蓝（默认）或石墨（`?ball=ink`）双态；去掉外描边和绿点。
- 实心旗标替代线条旗标；badge 改琥珀色，只在有「待处理」时出现。
- 连接降级时右下角才出现一个琥珀点；忙时用一圈脉冲，不额外加点。
- hover / 键盘 focus 才在球左侧展开文字标签「指挥官 / 3 项待处理」；面板打开时不显示，避免挡面板。
- C 的面板头部不再重复放「待处理 N」；面板内唯一入口是输入框上方的「3 项待处理」浮钮（抽屉打开时由抽屉标题承担计数）。

## 这次改了什么

1. **动作卡移出对话流**：`ApprovalFloatCard`、`DispatchConfirmCard` 不再作为 `.dshc-panel-body` 的子节点和消息混排。A 放进独立坞，B 放进右栏，C 放进抽屉。
2. **协议原文变成「决策记录」**：`[dispatch-confirm]` 不再直接铺在蓝色气泡里。默认一行结构化摘要（采用建议 / 自定义 / 取消 · 目标 · 时间），点开才看原始协议文本，保留可审计性。
3. **绑定信息变成数据**：会话、工作区、模型、连接状态分开展示；A/C 有浮层，B 常显；都带「打开会话 / 换绑」。
4. **进行中的任务可见**：状态、进度、最近更新；A 可展开任务轨，B 单独 tab，C 收进状态浮层。
5. **提示有位置**：连接降级用一条可重试/可忽略的横幅；输入区 hint 同步反映实时/轮询/处理中。
6. **审批队列**：多条审批在 A 用 `‹ 1/2 ›` 切换，B 平铺，C 在抽屉里平铺；处理完自动收起。
7. **审批仍是界面层**：允许/拒绝不会写进对话，也不会进入指挥官上下文；卡片和抽屉脚注都明确写了。
8. **键盘/焦点**：Enter 发送、Shift+Enter 换行；Esc 先关浮层/抽屉，再关面板；打开面板聚焦输入框，操作后保留输入焦点。
9. **悬浮球收敛信号**：计数、连接异常、忙碌三种状态各有出口，不再用红 badge + 绿点 + 描边同时喊。

## 可点的路径

1. A 的「采用建议」→ 卡片变成等待条 → 3.2 秒后任务 2 进入运行、坞切到审批、任务轨显示「进行中 2 +1」。
2. A 的「自定义选择」→ 工作区/新建或已有会话 → 确认派发；表单已压缩到一屏内，不再被坞裁掉。
3. A 的「审批 2」→ `‹ 1/2 ›` 切换 → 拒绝/允许本次；允许后面板顶部计数减一。
4. 绑定行 / 状态条 → 浮层；B 的「换绑」也走同一入口（原型里只弹 toast）。
5. 浮条「断线」→ 顶部提示条出现；「重试」或浮条「重连」恢复。
6. C：默认收起抽屉，只留「3 项待处理」的浮动入口；点开后可逐条处理，全部处理完自动收起。
7. 关掉面板（右上 × 或 Esc）→ 只剩球；点球重新打开（有未处理时 C 会直接展开抽屉）。
8. 浮条「状态」→ 左下角 JSON，确认当前 phase / 计数 / sheet 状态。

## 数据与边界

- 数据是示例：1 个待确认派发、2 条工作会话审批、1 个进行中任务 + 1 个待派发任务；字段按 `TaskView` / `PendingDispatchView` / `PendingApproval` 的语义手写，没有引入新业务字段。
- 纯本地演示态：无 Host、无 SSE、无持久化；允许/拒绝只移出本地列表，不会真的回答审批。真实实现仍必须走 `POST /commander/message` 和官方 `PendingApproval.answer()` 的 `answerable` 守卫。
- 「总是允许」没有放入原型：当前实现只支持「允许本次 / 拒绝」，官方卡里才处理「总是允许」；如果后续 API 放开，可在审批卡主按钮上加拆分菜单。
- B 的 600 宽是提案；如果产品坚持 420，B 退化成 C 或 A 的 tab 方案。A/C 不动现有几何。
- 这是抛弃型原型，不接入 `Overlay.tsx`；选定方案后要按仓库 Host/Client 分层重写到 `packages/dsh-commander/src/client`，补 i18n 两份字典和 client harness。
