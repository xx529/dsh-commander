## 现在看的是哪一套

默认进来就是**组合方案**，只有一套看板：

- 对照方案仍在浮条：**A**（六列 + 表格回收站）、**B**（分组列表 + 主从详情）、**C**（纯依赖视图，不参与组合）。

## 为什么去掉视图切换

| | 两视图切换（上一版） | 六列内悬停（现在） |
|---|---|---|
| 版面 | 多一个切换控件；切过去就没有状态列 | 一套布局，状态永远在 |
| 看依赖 | 要主动切模式，再找节点 | 鼠标放上去就有，离开即消失 |
| 找任务 | 图上选中后再「在六列中查看」 | 不用跳，卡就在原位 |
| 全局拓扑 | 依赖视图给全局 | 悬停给局部；全局仍可切对照 C |
| 代价 | 多一次模式切换 | 长链跨列时线会穿过淡出的卡片 |

结论：**六列是默认且唯一的看板**；依赖作为 hover 层出现，不再占视图位。

## 回收站：现在的坑与落地方式

### 现状（已核对代码）

- Host 的 `GET /commander/archive?limit=&cursor=` 本来就支持分页：`limit` 1..100、`cursor` + `nextCursor`（`src/host/api/routes/handlers.ts:214`、`m2m3-contract-patch.md §2.5`）。
- Client 端 `loadArchive()` 调的是 `fetchArchive(baseUrl)`，**默认 limit=50 且忽略 `nextCursor`**（`src/client/store.ts:531`、`src/client/state.ts:731`）。
- `TrashPane` 把 `trash.tasks` 一次性 `map` 成行，没有页码、搜索、筛选、批量操作（`src/client/BoardPage.tsx:382`）。

准确说法是：**当前只看得到前 50 条，第 51 条之后不可达；如果改成一次拉全量再渲染，DOM 会随条数线性膨胀，几千条就开始卡。**

### 三条硬规则

1. **服务端分页**：时间流每批 60 条（`limit=60`）、表格每页 50 条；`limit` 不超过 100（Host 已限制）。
2. **DOM 只保留当前批次/当前页**：时间流是「已加载的 100 条」，表格是「这一页的 50 行」；不能只追加不设上限。
3. **搜索/筛选在服务端**：否则只能搜当前页，是「假搜索」。原型里的关键词、状态、工作区、月份，对应新的查询参数。

### 需要的接口改动（先在契约里写）

```http
GET /commander/archive?limit=60&cursor=<updatedAt>
    &q=<关键词>&status=archived|cancelled&workspaceId=<id>&from=<ms>&to=<ms>
```

```json
{ "ok": true, "tasks": [], "nextCursor": 1732490000000, "total": 1284, "rev": 42 }
```

- `total` 是**过滤后**的总数，统计卡、月份导航的条数、「已渲染 N / 总数」都靠它；未过滤的总数可用快照里的 `archiveSummary`。
- 时间流只需要「加载更早」：游标顺序翻页即可，不需要跳页。
- 如果还要保留 A 那种页码：要么客户端维护游标栈（只做上一页/下一页），要么接受 `offset`/`page` 参数并返回 `total`；归档数据更新频率低，offset 漂移风险可接受。
- `limit` 上限保持 100；每页 100 时 1 万条也就 100 页，不会一次进 DOM。

### 批量恢复

- 现在只有单条 `POST /commander/tasks/:id/restore`（人专用），没有批量路由。
- 建议先做**客户端串行调用 + 逐条结果**，失败停在失败项并提示；要一键恢复再改契约加批量路由，不要在 Client 里拼并发绕过 actor 校验。

## 依赖展示：能直接做什么

数据已经够用，不需要新接口：

- `TaskView.dependsOn / waitingFor / ready` 都在快照里（`packages/dsh-commander/src/client/types.ts:197`、`types.ts:488`、`board.ts:402`）；
- 卡片只要一个 `id → title` 映射（快照 `tasks` 最多 200 条）；`waitingFor` 只包含未完成的前置，标题一定在快照里；若前置已归档，降级成 id 或「已归档」；
- 悬停高亮、连线、固定都只是读，不改状态，符合「依赖只提醒指挥官、不自动派发、不自动改依赖任务状态」；
- 连线坐标由客户端按卡片实际位置计算，不需要 Host 提供布局数据；
- 归档列表只返回摘要字段（`tasks[]` 无 `dependsOn`），所以回收站不展示依赖。

## 实现要点（组合方案）

- 悬停只加/删卡片 class 和重画一个 SVG 覆盖层，不触发整页 re-render，滚动位置不丢。
- 连线带底色 casing；等待中琥珀虚线 + 箭头，已验收的绿色点线；只连关联闭包内的任务。
- 列内滚动、横向滚动、窗口 resize 都重算连线；切 tab / 换方案清空固定态。
- 键盘 `Tab` focus 走与 hover 同样的高亮逻辑，`Enter` 固定/取消。
- 卡片闸门仍然回答「还差几个」，连线回答「卡在哪一环」，两者不重复。
