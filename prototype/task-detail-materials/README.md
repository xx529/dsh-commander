# 多轮任务详情 · 依据与材料 · 页面设计

> 日期：2026-11-20
> 基础：`prototype/task-detail-multiround/`（任务详情 v3，多轮编年）
> 目标：在「整理报告」的结论下面补 **链接 / 文档 / 图片** 三类材料，让结论可复核、可打开、可追溯来源，同时不破坏多轮结构和「指挥官不评估」的边界。
> 状态：静态设计稿，不含生产代码；截图里的配置/对比图是本地 mock 素材。

## 要解决的问题

现在的「整理报告」只有两样东西：

1. 一段**结论**（`reportSummary`，纯文本）；
2. 一列**验收项**，每项的 `evidence` 是一行纯文本。

工作会话真正产出的截图、配置、PDF、外链文档都进不了页面。用户想核对结论时只能：

- 回工作会话翻消息；
- 或者从纯文本里复制路径/URL 自己找。

这让「待验收」变成了「先相信指挥官，再自己找证据」。本设计把材料放回报告旁边，并明确标注来源与校验状态。

---

## 设计决策

### 1. 材料属于「这一轮的整理报告」，不是独立文件页

- 每个轮次的报告事件内部，顺序固定为：
  **结论 → 依据与材料 → 验收**。
- 不和「任务级交付物」混在一起；历史轮折叠时材料也一起折叠，摘要里保留 `N 项材料`。
- 这样材料的语义是「支撑本轮结论的来源」，不是「这个任务产出过的所有文件」。

### 2. 三类材料，两种呈现

| 类型 | 呈现 | 交互 |
|---|---|---|
| 图片（截图/示意图） | 2 列缩略图 + 标题/来源 | 点击打开大图预览，可左右切换 |
| 链接（含外链文档） | 列表行：标题 + 域名 + 来源 | 点击外部打开；明确标「外部链接，未校验」 |
| 文档（本地 PDF/XLSX 等） | 列表行：标题 + 类型 + 大小 + 来源 | 点击打开动作单：复制路径 / 在访达中显示 / 打开文件 |

图片优先，因为截图是结论最直接的可视证据；链接和文档在后，保持扫读效率。

> 原型中外链点击用 toast 演示，不真的跳转；图片预览、文件动作单是可操作的真实弹层。

### 3. 摘要 + 展开，避免材料把验收挤出首屏

- 默认显示 2 张图 + 前 3 行（链接/文档）；
- 底部 `查看全部 7 项` 展开剩余材料，展开后变 `收起`；
- 顶栏 `收起` 可把整块收成一行，只留计数和分类摘要；
- 结论卡底部加 `2 张截图 · 3 个来源 · 2 份文档` 和 `查看依据`，让结论和材料在视觉上绑定。

### 4. 来源和校验状态必须可见

材料行第二行固定标注来源：

- `工作会话交付`：来自 DSH `present` / 交付声明，路径已经过 Host 校验；
- `指挥官整理`：来自 `organize_report` 的显式材料，未经独立校验；
- 外链统一标 `外部链接，未校验`；
- 文件缺失/过大/类型不支持时显示 `已缺失` / `文件过大`，不静默消失。

这保持「指挥官不评估」：页面只说明“来源是什么”，不暗示“已经验证通过”。

### 5. 验收项挂材料 chips

每条验收项在 `证据 · …` 文本下面增加一行紧凑 chips：

- `配置截图`（打开大图）
- `依赖清单.xlsx`（打开文件动作单）
- `兼容性评估.pdf`
- `发布记录`（外链）

chips 只放 1–2 个最直接的材料，更多材料仍在报告级材料区。这样用户逐条验收时不用回到上面找图。

### 6. 不把材料做成文件浏览器

- 不显示工作区目录树、不支持上传、不做图片编辑/标注；
- 不在任务记录里存文件内容或 base64；
- 本地图片通过 Host 的签名资产路由读取，材料记录只存路径/URL/元数据；
- 远程图片直接加载，不加 Host 侧抓取（避免 SSRF）。

## 状态与边界

| 场景 | 页面表现 |
|---|---|
| 没有材料 | 不显示「依据与材料」块；结论卡也不显示材料摘要 |
| 只有链接 | 不显示图片画廊，列表直接顶到材料块顶部 |
| 材料很多 | 默认 3 行 + `查看全部 N 项`；展开后列表滚动跟随抽屉 |
| 图片缺失 | 缩略图位置显示文件占位 + `图片已缺失`，可复制路径 |
| 文件过大 | 行内标 `文件过大 · 仅记录路径`，不提供预览 |
| 历史轮折叠 | 轮次摘要保留 `N 项材料`；展开后看到该轮材料 |
| 浅色主题 | 所有材料 token 走 `styles.css` 的 light 变量，图标底色单独降饱和 |

## 落回生产需要的数据/接口（草案）

> 与上一轮可行性分析一致；这里只列页面依赖，不代表已实现。

```ts
type MaterialKind = 'link' | 'file' | 'image'

interface ReportMaterial {
  id: string
  kind: MaterialKind
  title: string                 // ≤200
  url?: string                  // link / 远程图
  path?: string                 // file / 本地图（绝对路径）
  description?: string          // ≤500
  source: 'presented' | 'commander' | 'session'
  acceptanceId?: string         // 可选：关联验收项
  derivedFrom?: { sessionId: string; seq: number }
  state: 'ok' | 'missing' | 'too_large' | 'unsupported' | 'unverified'
  meta?: { mime?: string; bytes?: number }
}
```

| 需求 | 落点 |
|---|---|
| 每轮报告材料 | `TaskRecord.reportMaterials?: ReportMaterial[]`（只存最新一轮，或按 `round` 分组） |
| 工作会话交付 | 读会话事件 `deliverables/presented`（`{turn, callId, files:[{path, description}]}`），按 turn/seq 归并 |
| 指挥官显式材料 | `organize_report` 新增 `materials[]` 入参；Host 校验后落库 |
| 图片预览 | `GET /commander/tasks/:id/materials/:materialId`，签名 + 过期 + 只读 + 大小/类型校验 |
| 任务详情 | `GET /commander/tasks/:id` 返回 `reportMaterials[]`；快照仍只带计数，避免 SSE 膨胀 |
| 旧数据 | `reportMaterials` 为可选字段；旧记录不显示材料块，不报错 |

安全约束：

- 只允许任务工作区内的路径，或本报告窗口内 `present` 过的绝对路径；
- `realpath` 后校验，拒绝符号链接逃逸、目录、设备文件；
- 图片只允许 PNG/JPEG/WebP/GIF，限制 8MB，拒绝 SVG 内联；
- 资产 URL 不携带文件路径，只携带 materialId + HMAC 签名；
- 远程 URL 只做 `http(s)` 语法校验，不在 Host 侧抓取。

## 待确认

1. **材料归属**：报告级统一材料区（当前设计）是否足够？还是每条验收项都要有独立的材料列表？
2. **图片默认展开数量**：当前 2 张 + 3 行；如果工作会话截图很多，是否改为 3 张横滑？
3. **本地文档打开方式**：当前动作单是“复制路径 / 在访达中显示 / 打开文件”；生产是否要直接接 DSH Sidebar 预览？
4. **历史轮材料**：历史轮折叠时只保留 `N 项材料`，展开才看；是否需要“查看该轮全部材料”的独立入口？
