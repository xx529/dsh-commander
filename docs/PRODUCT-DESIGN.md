> 日期：2026-11-17　状态：设计定稿（一期范围）

## 1. 一句话定义

**跑在 DSH 里的 AI 指挥官：你用一句话下命令，它澄清、用 Jev 判定派发目标、把任务交给合适的工作区会话，维护看板，并把工作会话的产出整理成任务与验收内容；只有派发置信度不足和最终验收才需要你拍板。**

### 1.1 职责边界（本轮最重要的一条）

| 角色 | 做 | 不做 |
|---|---|---|
| **指挥官** | 澄清需求、调 `commander_task_dispatch`、维护任务状态与看板、**整理工作会话的产出为验收内容并更新看板**、播报 | **不拆分工作**、**不评估**、不执行、不碰审批 |
| **Jev** | 对"派到哪个工作区/会话"给出带置信度的判定 | 不生成任务、不拆分、不评估 |
| **工作会话** | 自己拆分工作、执行、交付、在会话里说明产出 | 不定义验收流程、不写验收清单、不维护看板、不做派发决策 |
| **你** | 低置信度派发确认、审批、验收、人工改看板 | —— |

> **术语**：本文的"工作会话"= 被派发的普通 DSH 会话（新建或已有），不是子代理、不是子进程。

一期只在 DSH 内部：悬浮球 + 指挥面板 + 看板页 + 设置页，无系统级原生窗口。

## 2. 问题

🔶 **Assumption**：目标用户在 DSH 里同时推进 3–8 个工作区，习惯把整块工作丢给 AI，然后切走。

| 断点 | 现状 | 需要 |
|---|---|---|
| 入口断 | 命令要回 DSH 窗口下 | 应用内常驻悬浮入口 |
| 派发断 | 手动选工作区、选会话，选错就返工 | **Jev 判定 + 低置信度才问人 + 可自定义** |
| 跟踪断 | 任务散在多会话 | 指挥官自主维护的看板 |
| 审批断 | 审批会污染主对话 | 界面层直接处理，不进指挥官 |
| 收尾断 | 没有验收动作 | 指挥官整理产出与证据，人确认 |

### 2.1 非目标

- 不做多人协作、团队权限、多设备同步（一期）。
- 不替代 DSH 主界面。
- 不做通用 to-do（看板只放任务）。
- 不做自动验收、不做全自动派发。
- **不要求指挥官理解怎么完成工作**：它只关心"做什么、交给谁、到哪一步"。

## 3. 概念模型

```
命令 Command ──1..n──> 任务 Task
                         ├── 派发决策 DispatchDecision（Jev 判定 + 人工确认/自定义）
                         ├── 委派 Assignment（workspace + 会话 + brief）
                         ├── 验收内容 AcceptanceItem[]（指挥官整理，源自工作会话产出）
                         ├── 交付物 Deliverable
                         └── 事件流 TaskEvent（进展/交付/看板改动/验收）
```

### 3.1 任务状态机

```
draft(澄清中) ──建卡──> proposed(待派发确认)
   │                        ├── 置信度≥阈值且一致 → queued → running
   │                        └── 低置信度/不一致/自定义 → 等你确认 → queued
   ├──取消──> cancelled
   └──受阻──> blocked ──催办/改派──> running
                                   │
                             交付──> review(待验收)
                                   ├──通过──> done
                                   └──返工──> running
```

- 没有 `needs_you`：审批/提问不是任务状态。
- `blocked` 由指挥官根据会话事件判定；你可以在看板改。
- 看板列：待派发确认（draft/proposed）/ 进行中（queued/running）/ 受阻（blocked）/ 待验收（review）/ 已完成（done）。

## 4. 派发决策（Jev + 自定义）

### 4.1 流程

```
指挥官模型：commander_task_dispatch(taskId, candidate{workspaceId, mode, sessionId?})
        │
        ▼
Host 工具 commander_task_dispatch：
  1. 候选集 = **允许派发的工作区** × {新会话, 附加到匹配会话}，最多 6 个
  2. 调 Jev：输入 = 任务目标 + 验收提示（来自你的原话）+ 工作区摘要 + 最近会话摘要
            （不回传代码正文）
     Jev 输出 = { ranked[], top{choice, confidence}, reasons[] }
  3. 门控：
     pass ⟺ top == candidate AND confidence ≥ 阈值（默认 80%）
     - pass → 按能力策略准备本次会话能力（继承 / 自动选择，范围由能力面板决定）、派发、记账
     - fail → 不派发，返回 clarify：
              "Jev 建议 X（62%，低于阈值），请向用户确认候选与理由。"
  4. 指挥官向用户展示确认卡；用户可：
       a) 采用建议
       b) **自定义选择**：选工作区 + 选已有会话 / 新建会话
       c) 取消
  5. commander_task_dispatch(..., confirmed:true, confirmedBy:'user', finalTarget, capabilityNeeds?) → 按能力策略准备"本次会话"的能力并派发
```

### 4.2 门控规则

| 条件 | 行为 |
|---|---|
| 置信度 ≥ 阈值 且一致 | 自动派发，不打扰 |
| 置信度 ≥ 阈值 但 Jev 与模型不一致 | 暂停，两套方案都给用户 |
| 置信度 < 阈值 | 暂停，给 top-3 + 置信度 + 原因 |
| Jev 超时/不可用 | 默认暂停并询问（可配置"用模型判断"） |
| 用户自定义目标 | 以用户选择为准，记录 override |

### 4.3 自定义选择（本轮新增）

确认卡除了「采用建议」，必须有「自定义选择」：

- **工作区**：只列出允许派发的工作区，显示名称 + 摘要。
- **会话**：`新建会话` 或该工作区下已有会话（显示标题、最近活动、上下文水位）。
- 选定后「确认派发」；记录 `outcome: overridden`，任务决策记录里展示 `Jev 62% → 你选择 HtDot · 新建会话`。

### 4.4 回放

记录候选集、Jev 输出、模型建议、最终目标、是否 override、耗时；任务详情可查看 Jev 明细。一期不做自动学习。

## 5. 工作区配置（本轮新增）

### 5.1 允许派发的工作区（白名单）

- 设置页「工作区」中勾选允许指挥官使用的工作区；**未勾选的不会进入候选集**。
- 支持添加工作区（从 DSH 已有工作区中选）。
- 若全部未勾选 → 派发直接暂停，提示先配置。

### 5.2 工作区摘要

每个工作区有一份**工作内容摘要**，用于 Jev 判定与确认卡展示：

- 人工定义：一句话说明这个工作区是做什么的（如"电商后台：订单、结算、导出链路"）。
- 或模型总结：点击「生成摘要」，由模型读取该工作区最近会话标题/任务（**不读代码正文**）生成，可编辑后保存。
- 摘要为空的工作区仍可派发，但会在确认卡上提示"该工作区未配置摘要"。

### 5.3 能力选择：两种策略，逻辑完全交给能力面板

每个工作区只配置两种策略，只对"派发新建会话"生效：

| 策略 | 行为 |
|---|---|
| **继承工作区**（默认） | 不调用能力面板，新会话沿用工作区默认能力 |
| **自动选择** | 派发时把任务 brief + 指挥官润色的 `capabilityNeeds` 作为 draft 交给能力面板，由面板的 `jev.rank` + `jev.apply` 决定本会话启用哪些能力 |

**权力边界（重要）**

- **指挥官只出建议**：在 `capabilityNeeds` 里写"任务可能需要的能力"（自然语言短语，如「浏览器自动化」「单测」）；它不需要知道工作区有哪些能力，也不指定能力名。
- **能力面板负责一切**：能力范围、Jev 配置、阈值、三维评分、Skills/MCP/Tools 的口径、会话级应用，全部由 DSH 能力面板提供；本插件不维护目录、不做匹配、不配置能力阈值。
- **系统只做调用**：`capabilityPanel.jev.rank({sessionId, draft})` → `capabilityPanel.jev.apply({sessionId, plan})`，然后把结果摘要写进任务记录。
- **失败回退**：面板不可用、rank/apply 失败 → 回退继承并继续派发，记录原因；不阻塞任务。
- **已有会话不应用**：策略只作用于新建会话；已有会话沿用自身配置。

规则：
- 会话级生效：只作用于本次新建会话，不修改工作区。
- 确认卡/任务详情展示摘要（启用/禁用数、耗时、fallback 原因），不展开大目录。
- 未配置策略时按"继承工作区"。
- 能力面板的入口在设置页「能力」处跳转，不重复实现。
- 能力面板有自己的 Jev 配置页（负责能力选择）；指挥官的「派发与 Jev」只负责工作区/会话选择，两者互不覆盖。

## 6. 看板：指挥官自主维护

### 6.1 谁改

- 指挥官自主增删改：建卡、改状态、改字段、归档（通过工具），不需要你确认。
- 你也能改：优先级/标题、取消、归档、恢复、继续派发；**看板不再支持拖拽改状态**。
- **验收只能由人触发**：`POST /accept` 是唯一 `review→done` 入口。

### 6.2 人工改动注入

```
你看板改动 → Host 记 board/user-edit（before/after、幂等 id）
          → 注入指挥官会话：[看板改动] … 请同步状态，不要回滚用户改动
          → 指挥官确认并调整后续跟进（不反向弹窗）
```

- 单向：看板 → 指挥官；指挥官改看板直接写。
- 30s 合并 + 幂等 + 只同步最终态。
- 不注入审批/提问。

### 6.3 看板不放什么

- ❌ 审批、提问（界面层直接处理）
- ❌ 闲聊、备忘
- ❌ Super Kanban 的项目/时间线/日程等能力

### 6.4 卡片快捷操作（本轮修正）

- 只保留：**打开会话**、**归档**。
- 不提供「催一下」按钮：是否需要追问由指挥官按策略自行决定，不由用户手动催。
- 受阻卡允许「改派」。

## 7. 验收：指挥官整理，工作会话产出，人确认（本轮修正）

- **工作会话只负责产出与汇报**：它做事、交付文件、跑测试，并在会话里说明做了什么；它**不定义验收流程、不写验收清单、不维护任务板**。
- **指挥官负责整理并更新任务板**：每轮结束/交付时，指挥官读取工作会话的消息、工具结果与交付物，**整理**成 `acceptance[]`（清单 + 证据）与 `evidence[]`，自动更新任务板与任务详情。这是指挥官的职责，不是工作会话的。
- **指挥官不评估**：它只做抽取、归并、补证请求，不打勾、不判"通过/不通过"；"3/3 证据齐全"只表示证据已附，不等于验收结论。
- **你确认**：逐项看证据 → 通过 / 返工。通过是唯一的人门。
- 证据不足时：指挥官向工作会话追问补证，或在任务上标"证据不足"，任务仍停在 `review`，等你决定。
- 返工：你的批注 + 未通过项 → 指挥官整理续做 brief 发回工作会话。

## 8. 审批与提问：只在界面层

- 工作会话的审批/提问 → Host 读 `pendingInteraction` → 推给悬浮层/通知。
- 卡片上除允许/拒绝/总是允许外，另有 **「打开会话」**：跳到对应会话处理更复杂的上下文。
- 直接 `answer()` 回填；与主窗口共享同一 `PendingApproval`（同一实例双处渲染，先答者生效，后答者被 `answerable` 拦下）。
- **不进指挥官上下文、不进任务事件、不进看板**。
- 卡片标注「工作会话审批 · 仅在界面处理」。

---

## 9. 跟进与播报

- 事件驱动：轮次结束、工具失败、交付时更新任务；审批/提问事件被过滤。
- 巡检：不做结果轮询。会话**非空闲且超过 20 分钟无活动**时，看板只显示“疑似停滞”徽标；不改状态、不自动追问。
- **没有用户侧「催一下」按钮**：追问是指挥官策略，不是用户操作。
- 播报：完成、待验收、受阻、低置信度待确认；合并 + 节流 + 静音时段。

## 10. 设置（本轮重排）

| 分组 | 内容 |
|---|---|
| **指挥官** | 会话绑定（当前工作区 + 会话）、模型、系统提示词策略、**能力入口（跳转 DSH 能力面板）** |
| **工作区** | 允许派发的工作区（勾选）、每个工作区的摘要（人工编辑 / 模型生成）、**能力策略（继承 / 自动选择）；能力范围与选择逻辑由 DSH 能力面板负责** |
| **派发与 Jev** | 服务商、Endpoint、**API Key 来源（环境变量 / 手动填写）**、Jev 模型、置信度阈值、超时、超时行为、自动选择工作区开关、**并发说明（无配置项）**、判定输入摘要 |
| **看板** | 默认项目、归档策略、人工改动同步开关、回收站 |
| **外观与通知** | 主题（跟随系统/浅色/深色）、悬浮入口位置、快捷键、播报频率、静音时段 |
| **关于** | 版本、Jev 连通性、测试连接 |

### 10.1 指挥官会话绑定（本轮新增）

指挥官本身是**某个工作区里的一个 DSH 会话**：

- 显示当前绑定：工作区路径 + 会话标题 + 会话 id（可复制）。
- 操作：**打开会话** / **绑定到新会话**（在该工作区新建一条会话并绑定）/ **选择已有会话**。
- 重新绑定后，旧会话保留在 DSH 中，不删除；指挥官的短期记忆随新会话开始。

### 10.2 能力（本轮修正）

- 不再在指挥官设置里罗列工具白名单。
- 显示「能力由 DSH 能力面板管理」+ **「打开能力面板」** 按钮（跳转现有 dsh-capability-settings 面板），在那里配置指挥官可用技能/MCP。
- 仍保留产品级硬约束：指挥官没有 shell/文件写入工具。

### 10.3 Jev（本轮修正）

- API Key 支持两种来源：**环境变量**（如 `JEV_API_KEY`，推荐）或手动填写（存 DSH 凭据库）。
- 移除「同工作区串行」「全局并发上限」两个配置项。
- 并发模型改为固定说明：**不同工作区的会话可并行；同一会话内的任务自动排队（queued）**。无需用户配置上限。
- 判定输入展示中增加「工作区摘要」一行。

## 12. 关键流程

### 12.1 主流程

1. 你点球输入命令 → 指挥官澄清 → 建任务。
2. `commander_task_dispatch`：模型建议 HtDot 新会话；Jev 62% < 80% → clarify。
3. 确认卡：建议 + 备选 + 原因；你可「采用建议」或「自定义选择」。
4. 派发成功 → 进「进行中」。
5. 工作会话自己拆分工作、执行；期间审批只在界面层处理（可「打开会话」）。
6. 工作会话交付 → 指挥官读取产出，整理验收清单 + 证据并更新任务板 → 任务转 `review` → 播报。
7. 你看指挥官整理的验收内容（标注"指挥官整理"）→ 通过 / 返工。

### 12.2 自定义派发

你点「自定义选择」→ 选 Mira → 选已有会话「知识库 RAG 重排」→ 确认派发；决策记录标注 `Jev 62% → 你选择 Mira · 已有会话`。

### 12.3 人工改看板

你把卡片拖到受阻 → 注入 `[看板改动] …` → 指挥官同步、不再追问 → 轻提示「已同步给指挥官」。

### 12.4 闲聊不建任务

直接回答；不确定时默认按问答处理，末尾给「要为此建任务吗？」（≤1 次）。

## 13. 界面规格

### 13.1 视觉：对齐 DSH

- 全部使用 DSH `--dsw-alias-*` 对应值，明暗双主题跟随 DSH。
- 背景 `#FFFFFF`/`#151517`；模块 `#F5F6F7`/`#232324`；卡片 `#FAFAFA`/`#212123`
- 文字 `#0F1115`/`#F9FAFB`、`#61666B`/`#CFD3D6`、`#81858C`/`#ADB2B8`
- 边框 `rgba(0,0,0,.10)`/`rgba(255,255,255,.12)`
- 语义：brand `#4176E6`、success `#22C55E`、warning `#F59E0B`、danger `#EF4444`、violet `#A78BFA`
- 字体系统栈 + PingFang SC；等宽 SF Mono。圆角 4/8/12/16/20/28；0.2s `cubic-bezier(.4,0,.2,1)`。

### 13.2 悬浮层

- 球 56px；角标 = 待派发确认 + 待验收。
- 审批卡：`允许 / 拒绝 / 总是允许` + **`打开会话`**。
- 面板 420×660；消息区滚动，输入区固定。

### 13.3 派发确认卡

- 标题 + 置信度（62%，阈值 80% 刻度）+ 说明。
- 候选 3 行（工作区 · 会话模式 · 百分比）。
- 原因一行。
- 操作：**采用建议**（主）、**自定义选择**（次）、取消（文字）。
- 自定义展开：工作区下拉 + 会话下拉（新建 / 已有）+ 确认派发。
- 底注：`决策 jev · typesafe/jev-1 · 1.2s · 低置信度必须人工确认`。

### 13.4 看板

- 六列（待派发/待运行/运行中/受阻/待验收/已验收；取消/归档在回收站）；卡片 12px 圆角、左 3px 状态条；**无通用状态拖拽**。
- 卡片徽标：依赖「等待 A 验收」、待确认、继续派发；抽屉进度五段（待派发→待运行→运行中→待验收→已验收），blocked 在运行中叠加受阻标记。
- hover 快捷操作只有「打开会话」「归档」；**无催一下**。
- 顶栏「看板由指挥官自动维护」+ 同步状态。

### 13.5 设置

- 左子导航：指挥官 / 工作区 / 派发与 Jev / 看板 / 外观与通知 / 关于。
- 指挥官：会话绑定卡（工作区 + 会话 + 打开/新绑/选择）、模型、系统提示词、能力面板入口。
- 工作区：勾选列表 + 摘要编辑（人工/模型生成）。
- 派发与 Jev：API Key 来源（环境变量/手动）、阈值 slider、超时、自动选择、并发说明。
- 不再出现并发上限与同工作区串行。

## 14. 数据模型

```ts
type TaskStatus = 'draft'|'proposed'|'queued'|'running'|'blocked'|'review'|'done'|'cancelled'|'archived'

interface Task {
  id: string; title: string; goal: string; status: TaskStatus
  workspace: { id: string; name: string; path: string }
  priority: 'low'|'normal'|'high'|'urgent'
  acceptance: AcceptanceItem[]           // 指挥官整理（源自工作会话产出）
  dispatch?: DispatchDecision
  assignments: Assignment[]
  primarySessionId?: string
  deliverables: Deliverable[]
  progress?: { label: string; pct?: number }
  blockReason?: string
  lastActivityAt: number; createdAt: number
  commandId?: string
  events: TaskEvent[]
}

interface AcceptanceItem {
  id: string; text: string; verify?: string
  evidence?: string
  source: 'commander'                    // 固定：指挥官整理
  submittedAt: number
}

interface DispatchDecision {
  id: string; at: number
  candidates: { choice: string; label: string; p: number }[]
  jev: { provider: string; model: string; top: string; confidence: number; reasons: string[]; ms: number }
  modelSuggestion: string
  outcome: 'auto'|'confirmed'|'overridden'|'cancelled'|'jev_unavailable'
  finalTarget?: { workspaceId: string; mode: 'new'|'attach'; sessionId?: string }
  confirmedBy?: 'user'
}

interface WorkspaceConfig {
  id: string; name: string; path: string
  allowed: boolean                       // 是否允许派发
  summary: string                        // 人工或模型生成
  summarySource: 'manual'|'model'
  summaryUpdatedAt?: number
  capabilityPolicy: {
    mode: 'inherit' | 'auto'            // 继承 / 自动选择（执行交给能力面板）
    lastSelection?: {
      status: 'applied' | 'fallback' | 'failed'
      enabled: string[]; disabled: string[]; durationMs?: number; reason?: string; at: number
    }
  }
}

interface CommanderBinding {
  workspaceId: string; workspacePath: string
  sessionId: string; sessionTitle: string
  model: { provider: string; model: string; reasoning?: string }
}

interface BoardEdit { id: string; taskId: string; field: string; before: unknown; after: unknown; at: number; injectedAt?: number }
```

存储：DSH `storageDomain`（state.json 原子写 + events.jsonl 追加 + board-edits.jsonl）。审批/提问不落任务账本。

## 15. 技术架构（一期）

```
DSH Web GUI
├── Client 插件（commander-ui）
│   ├── shell.overlay：球 + 面板 + 审批卡（含打开会话）
│   ├── 看板页：main keyed / 右侧栏 tab
│   └── 设置页（含工作区、Jev、能力入口）
│        ↕ 自建 HTTP/SSE /commander/*
└── Host 插件（commander）
    ├── 指挥官会话：sessionController.create/selectModel/prompt + 绑定/重绑
    ├── 会话创建：创建时应用能力策略（继承 / 自动选择；只在面板范围内）
    ├── 任务账本：storageDomain
    ├── commander_task_dispatch：白名单候选 + 工作区摘要 + Jev 门控 + 自定义确认
    ├── 能力策略：按工作区配置计算本次会话能力集，写入 session 能力设置（不改工作区）
    ├── Jev 客户端：环境变量或凭据库取 key
    ├── 事件订阅：turn/end、tool/result、deliverables；过滤审批/提问
    ├── 看板写入 + 人工改动注入
    └── 调度：会话级排队（同会话 queued），不同会话并行
```

- 无原生壳（二期）。
- 审批：只读 `pendingInteraction` 双处渲染，不新增 answerer。
- Host→Client 推送走自建 SSE。
- 能力面板复用 DSH 现有设置（不重复实现）。

## 16. 权限与安全

- 指挥官工具白名单：任务/派发/看板/播报；无 shell、无文件写、无构建。
- 能力（技能/MCP）由 DSH 能力面板管理，指挥官设置只提供跳转。
- Jev key 优先环境变量；手动填写时存 credential store，界面掩码。
- 判定输入只含任务目标、验收提示、工作区摘要、目录名与会话摘要（不含代码正文）。
- 看板注入只接受 Host 生成的 edit 事件。

## 20. 工具面与提示词

| 工具 | 作用 | 约束 |
|---|---|---|
| `commander_task_create` | 建任务（目标、你的原话） | 三条件下才建 |
| `commander_task_get` | 读单条最新任务（取 version/ready） | 只读 |
| `commander_task_update` | action：edit/set_dependencies/block/cancel/recover；必带 expectedRevision | 状态机约束；done/archived 不可写 |
| 人专用路由 | accept/archive/restore/cancel | 仅界面调用 |
| `commander_task_dispatch` | Jev 门控派发（支持自定义目标 + 能力清单） | 低置信度返回 clarify；确认后 `confirmed:true`；自动能力仅限工作区已启用项 |
| `commander_task_report` | 读取工作会话产出，整理验收内容并更新任务板 | 只整理、不评估 |
| `POST /accept` / `POST /continue` | 验收/继续派发 | 仅人触发 |
| `commander_task_list` | 查看看板 | 只读 |
| `brief_user` | 播报 | 节流 + 优先级 |

提示词要点：
1. 你是调度者，不拆分工作、不评估结果、不写代码。
2. 派发必须调 `commander_task_dispatch`，不要绕过 Jev 直接建会话。
3. 工具返回 clarify 时，原样给候选与置信度；用户自定义时以用户选择为准。
4. 看板可自主维护；用户改动以注入消息为准。
5. 审批/提问不属于你的上下文。
6. 工作会话只产出与汇报；验收内容由你整理并更新任务板，但不要评估通过与否。
